### Autopilot-full

**You own the verdicts, never the PRs. One owner carries each PR from build to merge, and nothing merges until your swarm, which never wrote the code, has proven the code that lands.**

A verdict covers one patch and green CI covers one head. Step 4 runs a full swarm once, and again only for a major change. The patch-id rule in `playbooks/shipping.md` can carry a lane's result, and every new head needs its own green CI.

1. **The operator's gates come first.** The grant covers only the queue's items, so items the operator names as theirs and PRs outside the queue stop at merge-ready. A request to state the plan is not a go.
2. **Assign one bounded owner per PR.** The parent resolves the forge and assigns explicit ownership, full goal/scope, evidence requirements, and allowed actions. Owners are native tasks sharing the workspace, not cloud agents. Disjoint writers or serialization are mandatory; isolated code candidates require the opt-in headless worktree runtime. Children cannot spawn verifiers, ask users, or manage the parent's todo list; the parent supplies all of those. Commit/push/PR creation/merge remain explicit user-authorized host-gated actions.

   The parent may open the PR early only with explicit user authorization. Code-ready requires the actual slop-strip dependency or a named equivalent driver, no-comments review, repo checks, and real-surface proof. Missing mandatory dependency or proof is BLOCKED. Rebase/push only when authorized; record each exact new head and re-evaluate receipts after every change.

   Keep durable local state in workspace `.pstack/runs/<run>/`, including each role, latest task ID, current head, evidence, and progress bound. Push only when explicitly authorized. Never force-push by default, even on an owned branch. Confirm a prior writer stopped before a replacement writes.
3. **Keep independent PRs unstacked where possible.** Queue owner assignments within maxWorkers (default 2). Native owners share workspace; do not parallelize overlapping writes or branch changes. Autopilot-stack may propose dependencies, but rebasing/restacking needs explicit authorization.
4. **Swarm-verify once.** A full swarm runs once, at the code-ready head. Another full swarm runs only for new behavior, a redesign, or a large new diff. A rebase, a merge-conflict resolution, or a minor fix gets a single verifier at the new head, and a wording-only change gets none. Fan out independent verifiers at the code-ready SHA per the **swarm** skill. They re-run the gates, prove the load-bearing behavior live on the real surface through its control skill (such as `control-ui` or `control-cli` from `cursor-team-kit`) or a named driver, and audit the diff. The verdict is not clean without the live lane, or before you audit the merge-ready report's receipts, because no lane trusts a claim it has not checked.

   Real bugs, failed gates, wrong shipped documentation, missing mandatory capabilities or evidence, incomplete required lane coverage, and missing user/forge approvals all block landing. Record inherited base defects without blaming the patch, but do not reinterpret a missing gate as a harmless follow-up.
5. **Only the parent may integrate verified work.** Child owners return code and evidence; the parent arranges independent verification and handles any explicitly authorized git/forge actions. Green CI or a verifier pass never grants merge authorization. Refresh CI and consequential proofs after an authorized rebase or head change.

   Right before an authorized merge, inspect current trunk, head, base, checks, and required receipts. If trunk changes the result, validate on the merge result. A lockfile or caller change needs the relevant executable check. Rebase only with authorization; if new permissions, drift, conflict, or a third rebase would be needed, hold and return the exact blocker rather than force progress.
6. **Keep approval separate from the verdict.** The parent audits receipts independently; a verifier countersign is evidence, not user or forge approval. Never weaken, soft-fail, or disable a mandatory gate to get green. Missing driver, lane, or independent result blocks merging.

   Execute one bounded turn by default, checkpointing unfinished work for manual resume. Continue autonomously only under a user-explicitly enabled host Goal and its limits. A native cron wake requires both an exposed capability and user-approved schedule; otherwise resume manually. Never use the host CodeRabbit-only `/loop` as a pstack scheduler, and do not create daemons, cloud services, or event subscriptions. On each authorized turn audit recorded heads, task IDs, frozen verification receipts, and progress. Stop a stalled writer, verify it stopped, then launch its replacement. A child owner requests parent-managed verification; it never fans out internally. Report changed operator-visible facts through ketchup.
7. **Stand down at once on the operator's stop.** A hold reaches every owner as a zero-writes order. Each reports where it stands and keeps its brief until the operator releases it.

**Reply:** catch the operator up per the **ketchup** skill, covering each PR's state and verdict, what merged, countersigns and why, open operator gates, and parked follow-ups, with links to each PR and the trails.
